# 05. Администраторы, посещения и апсейлы — план работ

Роль администратора: отмечает приход/уход по брони, принимает оплаты и оформляет продажи, **фиксирует апсейлы** — чтобы владельцу потом доначислять vendido админа.

## Роль и права

**Администратор** назначается владельцем. Видит: календарь студии целиком, все брони, продажи, склад (обзорно), балансы мастеров (обзорно). Может: создавать/редактировать брони (в рамках полномочий), отмечать начало/завершение/неявку, оформлять продажи и manual-платежи, вести свою смену. Не видит: ничего «чужого» сверх студии — мастера при этом видят только своё.

## Сущности

- **Смена (Shift)**: план (админ, интервал), факт (начало/конец, паузы), утверждённые оплачиваемые часы (утверждает владелец). **Часы покрытия считаются по сменам** — 4 мастера × 5 ч = 5 ч покрытия, не 20.
- **Посещение**: отметки по брони — фактический приход/уход (время + автор-админ). Ранний уход/поздний приход сами по себе не меняют цену (предоплата 100%); исключения — решением владельца через корректировку.
- **Апсейл (Upsell)**: запись, привязанная к продаже: admin_id, что продано (позиции sale), кому (мастер / клиент мастера), сумма, дата. По апсейлам — **доначисление (Payout)**: владелец задаёт правило (% от суммы апсейла) или фиксирует разовое доначисление с основанием; доначисления — отдельная сущность со статусом (начислено/выплачено).
- **Операционное исключение**: неявка, истёкший hold, бронь вне покрытия — список для админа/владельца.

## Бронь вне покрытия

При создании брони, выходящей за фактическое покрытие смен — флаг `требует_подтверждения` (владелец подтверждает) или недоступно (настройка).

## API (эскиз)

- `POST /admins`, `DELETE /admins/{user_id}` — владелец.
- `GET/POST /shifts`, `POST /shifts/{id}/start|/end`, `PATCH /shifts/{id}/approve`.
- `POST /bookings/{id}/visit/start|/end`, `POST /bookings/{id}/no-show` — админ.
- `GET /upsells?admin_id=&from=&to=`, `GET /payouts?admin_id=&status=`.
- `POST /payouts` {admin_id, сумма или % от апсейлов за период, основание}, `POST /payouts/{id}/mark-paid`.
- `GET /ops/exceptions`.

## UI

- Раздел «Админ»: текущие брони с кнопками «начать/завершить/неявка», касса (продажа), список исключений.
- Раздел «Смены»: план/факт/утверждение часов.
- У владельца: «Апсейлы» — таблица по админам (что продано, суммы, период) + начисление доначислений; «Выплаты» — статусы.

## Задачи

1. Роль admin в авторизации + guard'ы + навигация по ролям.
2. Модель: shifts, отметки посещения (в booking_events + поля факта), upsells (или sale.admin_id + отдельная сводка), payouts, ops_exceptions.
3. Логика: отметки, неявка (grace), покрытие и флаг подтверждения.
4. Апсейлы: при оформлении продажи админом она помечается как апсейл; отчёт по админам; доначисления (правило % + ручные) со статусами.
5. Фронтенд: экраны админа и владельца (апсейлы/выплаты).
6. Тесты: права, отметки, неявка, апсейл создаёт запись с автором, доначисление считается по правилу.

## Критерии готовности

- Админ отмечает приход/уход; завершение фиксирует фактическое время.
- Каждая продажа, оформленная админом, видна в «Апсейлах» с автором и суммой.
- Владелец начисляет доначисление по апсейлам и отмечает выплату.
