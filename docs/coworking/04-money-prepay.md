# 04. Деньги: 100% предоплата, баланс мастера, возвраты — план работ

Правило: **бронь подтверждается только полной оплатой стоимости; долгов нет**. Отмена ≥24ч до начала — 100% возврат; позже — удержание по правилу (параметр в настройках, базово 100%).

## Модель

**LedgerEntry** (проводка счёта мастера, append-only):
- тип: `topup` (пополнение), `charge` (списание за бронь/товар), `refund` (возврат), `adjust` (ручная корректировка — автор + основание обязательны);
- сумма, валюта, ссылки (payment_id / booking_id / sale_id), автор, дата, примечание.
- **Остаток = Σ проводок** (вычисляется; отдельного поля нет).

**Payment**: провайдер (эквайринг / manual), внешний id (уникальный — дедуп вебхука), сумма, статус (pending/paid/cancelled/expired), url, срок. 1 оплата = 1 проводка `topup`.

**Связь бронь–деньги (предоплата):**
- `POST /bookings` → сразу создаётся счёт (Payment, pending) на `final` из снимка расчёта + бронь в `ожидает_оплаты` с дедлайном hold.
- Оплата счёта (вебхук или manual) → `topup` + бронь → `подтверждена`. ИЛИ оплата **с баланса** (если хватает остатка) → `charge` → `подтверждена`.
- Дедлайн прошёл → бронь `истекла_оплата`, счёт → `expired`, место свободно.
- Отмена подтверждённой брони мастером (только до начала): возврат по ступеням `refund_tiers` в настройках (дефолт ≥24ч → 100%, ≥12ч → 50%, позже → 0%), `charge` удержания не нужен — невозвращённое просто остаётся у студии. Отмена по вине площадки → всегда 100% возврат.
- Неявка отдельно не отмечается: оплаченное время принадлежит мастеру, пришёл он или нет.
- Напоминание в Telegram «оплатите до ЧЧ:ММ» за `payment_reminder_minutes` (дефолт 120) до дедлайна оплаты.

## Сценарии

1. Мастер пополняет баланс (счёт → вебхук, дедуп, сверка суммы) → остаток растёт.
2. Мастер бронирует место → видит стоимость → «оплатить картой» (счёт apipay) или «с баланса» → бронь подтверждена.
3. Не оплатил за hold → истекла, место свободно, счёт expired.
4. Отменил за 3 дня → 100% возврат на баланс (или на карту — решаем с бухгалтером; MVP: на баланс).
5. Отменил за 18 часов → возврат 50%; за 5 часов → без возврата.
6. Админ принял наличные → manual payment (автор = админ) → проводка.

## Инварианты

- Дедуп вебхука по внешнему id; сумма вебхука сверяется со счётом.
- `charge` только в пределах остатка (lock счёта в транзакции; параллельные charge не уходят в минус — тест).
- Бронь в статусе `подтверждена/начата/завершена` всегда полностью оплачена — инвариант системы (никакого «долга»).
- Возвраты — отдельными проводками, история не стирается.
- Суммы: фиксированная точность 2 знака, округление на границе; без float.

## API (эскиз)

- `GET /me/balance` — остаток + выписка (мастер).
- `POST /me/topups` — счёт на пополнение → url.
- `POST /payments/webhook/{provider}` — подпись + дедуп + сверка суммы.
- `POST /bookings` → создаёт бронь + счёт; `POST /bookings/{id}/pay` {method: card|balance}.
- `POST /bookings/{id}/cancel` — применяет правило 24ч → refund/удержание.
- `POST /payments/manual` — админ.
- `POST /admin/ledger/adjust` — корректировка с основанием.
- `GET /admin/ledger?master_id=&from=&to=` — журнал (владелец/админ).

## UI

- Мастер: **«Баланс»** — остаток, пополнить, выписка; при создании брони — экран оплаты (карта/с баланса) с дедлайном hold.
- Владелец/админ: журнал денег, ручные корректировки, возвраты.

## Задачи

1. Модель: ledger_entries, payments (новый контур), связь с bookings; индексы; уникальность внешнего id.
2. Сервис денег: транзакционные topup/charge/refund/adjust с lock'ом; остаток вычисляется.
3. Провайдеры: эквайринг (счёт, вебхук HMAC+дедуп+сверка суммы, истечение), manual.
4. Интеграция с бронями: счёт при создании, pay (card/balance), hold→истекла, cancel→правило 24ч, неявка→удержание.
5. Фоновая задача: истечение pending-счётов и hold'ов.
6. Фронтенд: баланс мастера, экран оплаты брони, журнал у владельца.
7. Тесты: дедуп вебхука, сверка сумм, гонка charge, предоплата-инвариант (подтверждена ⇒ оплачено 100%), правило 24ч, возврат.

## Критерии готовности

- Бронь подтверждается только после 100% оплаты; не оплатил — истекла, место свободно.
- Отмена за ≥24ч возвращает 100%; позже — удержание по правилу.
- Повторный вебхук не дублирует; баланс сходится с журналом.
