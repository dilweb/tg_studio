# 03. «Настройка мест» и ценовая политика — план работ

Владелец динамически задаёт цены: утро/вечер, будни/выходные, праздники и особые даты, скидки — и меняет их под рынок без деплоя. Цены применяются к **новым** броням; подтверждённые не пересчитываются.

## Модель

**PriceRule** (ценовое правило):
- область: конкретное `seat_id` или NULL = все места;
- дни: `будни` / `выходные` / `все` / конкретные даты (список);
- интервал времени суток: [time_from, time_to) — «утро», «вечер» и т.п. (владелец задаёт произвольные интервалы);
- ставка за час (или фикс за бронь — MVP: за час);
- приоритет (чем выше, тем раньше применяется при пересечении правил);
- активность, дата создания.

**Особые даты**: правило с конкретной датой (праздник, «дорогой день») — по сути PriceRule с mode=date и высоким приоритетом. Отдельная таблица не нужна; в UI — вкладка «Праздники/особые даты».

**DiscountRule** (скидка):
- % или фиксированная сумма;
- условия: резидент (флаг на мастере) / определённые дни / промокод (вне MVP) / «при бронировании от N часов»;
- область: все места или конкретное; активность.

**BookingSettings** (настройки студии): мин. длительность брони, шаг времени, буфер между бронями, срок hold (дедлайн оплаты), grace-период для неявки, правило отмены (сейчас: ≥24ч = 100% возврат, <24ч = удержание X% — параметр).

## Расчёт стоимости брони

1. Интервал брони режется по границам: часы работы студии → дни/интервалы правил (с учётом приоритета и особых дат).
2. Каждая часть × ставку часа (пропорционально минутам) → сумма части.
3. `base = Σ частей`; скидки по DiscountRule → `discount`; `final = base − discount` (округление до 2 знаков на ит automaticamente).
4. В бронь сохраняется снимок: список частей (интервал, правило, ставка, сумма), base, discount, final, валюта, момент расчёта. Этот снимок — единственный источник стоимости брони дальше.

## UI «Настройка мест» (владелец)

- Вкладка «Места»: 4 карточки (имя, оснащение, активна), редактирование.
- Вкладка «Цены»: таблица правил (место/все, дни, интервал суток, ставка, приоритет), добавление/редактирование/удаление; быстрые пресеты («Буднее утро», «Выходные»).
- Вкладка «Праздники и особые даты»: дата → ставка/коэффициент.
- Вкладка «Скидки»: % для резидентов, промо, «при бронировании от N часов».
- Вкладка «Правила бронирования»: мин. длительность, шаг, буфер, hold, grace, правило отмены (24ч).
- Предпросмотр: «сколько будет стоить место №2 во вторник с 10:00 до 15:00» (калькулятор на произвольный интервал).

## API (эскиз)

- `GET/POST /price-rules`, `PATCH/DELETE /price-rules/{id}` — владелец.
- `GET/POST /discount-rules`, `PATCH/DELETE /discount-rules/{id}`.
- `GET/PUT /booking-settings`.
- `POST /pricing/quote` {seat_id, start, end, master_id} → части расчёта, base, discount, final, применённые правила. Не создаёт бронь.
- В `POST /bookings` сервер сам считает quote и пишет снимок в бронь.

## Инварианты

- Нет цены → бронь создать нельзя (409 «не задана цена на этот интервал»), владелец видит предупреждение в настройках.
- Подтверждённая бронь хранит снимок; смена правил не меняет её (тест).
- Перенос/продление → новый расчёт по актуальным правилам + запись в историю.

## Задачи

1. Модель: price_rules, discount_rules, booking_settings; снимок в bookings.
2. Движок расчёта (разрезание интервала, приоритеты, особые даты, скидки); юнит-тесты границ (ровно на границе, пересечение 2–3 интервалов, смена суток, выходные, праздник поверх обычного дня).
3. CRUD правил + пресеты в UI.
4. Калькулятор quote в UI + `POST /pricing/quote`.
5. Интеграция с бронями (док 02): снимок в бронь, история пересчётов.
6. Тесты: версии/снимки, округление, 409 без цены.

## Критерии готовности

- Владелец меняет цену часа места «вечер в пятницу» — новые брони считаются по ней, старые подтверждённые — по старому снимку.
- Мастер до оплаты видит полную разбивку стоимости.
- Праздник/особая дата переопределяет обычную цену на дату.
