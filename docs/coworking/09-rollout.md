# 09. Порядок внедрения (v2) и Definition of Done

## Порядок итераций

1. **01** — модель зафиксирована (документы согласованы).
2. **02** — 4 места + календарь каждого места + брони с защитой от пересечений/дублей + hold/TTL.
3. **03** — «Настройка мест»: ценовые правила (утро/вечер, будни/выходные, праздники, скидки), калькулятор, снимок в брони.
4. **04** — деньги: 100% предоплата, баланс мастера, вебхук/дедуп, правило отмены ≥24ч = 100% возврат.
5. **05** — админ: отметки посещений, смены, апсейлы + доначисления.
6. **06** — склад + продажи (апсейлы, разовые контакты).
7. **07** — дашборд владельца на главной, отчёты, Excel для бухгалтера.
8. **08** — чистка legacy (dev, данные сносим); бота нет, уведомления — только исходящие через Bot API (`modules/notify.py`).

Каждая итерация: модель+миграция → сервис → API → UI → тесты → smoke.

## Риски

| Риск | Митигция |
|------|----------|
| Двойная бронь при параллельных запросах | lock/constraint + тест на N запросов |
| Смена цен задела подтверждённые брони | снимок расчёта в брони + тест |
| Дубль вебхука | дедуп по внешнему id + тест |
| «Долг» возник неявно | инвариант: подтверждена ⇒ 100% оплачено; UI не даёт «завершить в долг» |
| Часы покрытия посчитались как сумма часов мест | покрытие по сменам; тест 4×5=5 |
| Апсейл без автора | sale.admin_id обязателен при оформлении админом |
| Excel не сходится с банком | каждая строка отчёта = внешний id платежа; тест сверки |

## Definition of Done

- Мастер: видит календари 4 мест → бронирует → видит цену (разбивка) → оплачивает 100% (картой или с баланса) → видит баланс и историю.
- Не оплатил за hold → бронь истекла, место свободно. Отмена ≥24ч → 100% возврат.
- Админ: отмечает приход/уход, оформляет продажу с фиксацией апсейла; владелец доначисляет по апсейлам.
- Владелец: главная = дашборд (загрузка 4 мест, выручка, апсейлы, тревоги); «Настройка мест» меняет цены без деплоя; Excel по выручке уходит бухгалтеру.
- Legacy вычищен; бот/AI не ведут «запись клиентов».
