# 01. Доменная модель ковркинга (v2)

Dev-среда: старые тестовые данные можно удалять, миграций сохранения истории не делаем. Модель — чистая, без legacy-якорей.

## Субдомены

```
Площадка (Space)       — 4 места, их календари, блокировки, часы работы студии
Бронирование (Booking) — заказ места мастером, 100% предоплата
Цены (Pricing)         — правила цены часа: утро/вечер, будни/выходные, праздники, скидки
Деньги (Money)         — баланс мастера, платежи, возвраты; долгов нет
Персонал (Staff)       — администраторы, смены, апсейлы и доначисления
Склад/Продажи (Stock)  — товары, движения, продажи (апсейлы)
Дашборд/Отчёты (Dash)  — наблюдаемость владельца, Excel для бухгалтера
```

## Сущности

### Площадка
- **Студия**: название, таймзона, часы работы по дням недели.
- **Место (Seat)** — ровно 4 в MVP: имя/номер, описание/оснащение, активность, **собственный календарь** (лента событий этого места). У места могут быть индивидуальные ценовые правила (или общие — решает владелец в настройках).
- **Блокировка (SeatBlock)**: интервал + причина (уборка/ремонт/закрыто) — блокирует календарь места.

### Бронирование
- **Бронь (Booking)**: мастер, место, [start, end), статус, hold_deadline, применённые ценовые правила (снимок расчёта), итоговая стоимость, фактическое время (отметки админа), история событий.
- **Статусы (операционные):** `ожидает_оплаты` (hold) → `подтверждена` (100% оплачено) → `начата` → `завершена`; ветки `отменена_мастером`, `отменена_площадкой`, `неявка`, `истекла_оплата`.
- **Финансы:** т.к. предоплата 100% — у состоявшейся брони всегда `оплачена`. **Долга не существует**: либо полная оплата до начала, либо бронь не подтверждается. Отмена → возврат/удержание по правилу.
- **Hold**: бронь в `ожидает_оплаты` с дедлайном; по истечении → `истекла_оплата`, место освобождается.

### Цены
- **Ценовое правило (PriceRule)**: область (конкретное место или все), дни (будни/выходные/конкретные даты), интервал времени суток (утро/вечер/ночь или произвольный), ставка за час, приоритет. **Особые даты** (праздники, «дорогие дни») — правила с конкретной датой и высоким приоритетом.
- **Скидка (DiscountRule)**: % или фикс, условия (резидент, определённые дни/часы, промо) — применяется поверх.
- Правила действуют **на новые брони**; у подтверждённой брони хранится снимок расчёта.
- Расчёт: интервал брони режется по границам правил → части считаются по своим ставкам → скидка → итог. Снимок (части, ставки, итог) сохраняется в бронь.

### Деньги
- **Баланс мастера (Ledger)**: append-only проводки — `пополнение`, `списание` (за бронь/товар), `возврат`. Остаток = Σ проводок (вычисляется, не хранится отдельно).
- **Платёж (Payment)**: внешний (эквайринг) или manual (админ принял наличные/перевод); дедуп вебхука по внешнему id; одна оплата = одна проводка.
- **Резерв под бронь** не нужен как отдельная сущность при 100% предоплате: либо оплата прошла (бронь подтверждена), либо hold истёк. Упрощение: при создании брони сразу выставляется счёт на полную стоимость.

### Персонал и апсейлы
- **Администратор**: роль, назначается владельцем.
- **Смена (Shift)**: план/факт/утверждённые часы (часы покрытия считаются по сменам, а не по сумме часов мест).
- **Апсейл (Upsell)**: запись о продаже, оформленная админом: что продано (товар/услуга ухода), кому (мастер / клиент мастера), сумма, дата, связь с продажей. По апсейлам владельцем считаются **доначисления** (например, % от суммы) — доначисление фиксируется отдельной записью с основанием.

### Склад и продажи
- **Товар (Product)**: остаток, закупочная цена, цена продажи, порог.
- **Движение**: приход/продажа/внутреннее потребление/возврат/корректировка.
- **Продажа (Sale)**: позиции, покупатель (мастер со счётом или разовый контакт), сумма, оплата, автор (админ = апсейл), связь с бронью опционально.

### Дашборд
- Срезы «сейчас/за период»: загрузка 4 мест, активные/новые брони, выручка (оплаченные брони + продажи), отмены/неявки/удержания, апсейлы по админам, остатки склада ниже порога, балансы мастеров (сколько внесено и не потрачено).

## Сквозные инварианты

1. Нет пересекающихся активных броней одного места (вкл. блокировки); проверка на сервере + защита от гонок.
2. Параллельные запросы не создают двойную бронь.
3. Бронь подтверждается **только 100% оплатой**; «долг» невозможен.
4. Hold истекает по дедлайну, место освобождается.
5. Отмена ≥24ч до начала — 100% возврат; позже — удержание по правилу (параметризовано).
6. Изменение цен не меняет подтверждённые брони (снимок расчёта в брони).
7. Повторный вебхук не создаёт вторую проводку.
8. Суммы — фиксированная точность (2 знака), округление на границе операции.
9. История (броней, денег, продаж) append-only; исправления — сторнирующими записями.
10. Все времена — UTC на хранении, таймзона студии на границах.
11. У каждого из 4 мест — свой календарь; календарь студии = их объединение.
12. Каждая продажа, оформленная админом, имеет автора (апсейл) — база для доначислений.

## Жизненный цикл брони

```
создана → счёт на 100% стоимости (hold, дедлайн оплаты)
   ├─ оплачено до дедлайна ─────► подтверждена
   └─ дедлайн прошёл ───────────► истекла_оплата (место свободно)

подтверждена
   ├─ отменена мастером (только до начала) ► отменена, возврат по ступеням (≥24ч 100%, ≥12ч 50%, позже 0%)
   ├─ отменена по вине площадки ────────► отменена, 100% возврат
   └─ время брони вышло ────────────────► состоялась (ручных отметок нет; мастер может
                                          подтвердить присутствие кнопкой в напоминании
                                          Telegram — аналитика владельца, на деньги не влияет)
```
