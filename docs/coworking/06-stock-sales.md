# 06. Склад и продажи (апсейлы) — план работ

Склад с двумя видами списания: **обеспечение площадки** (расход студии, бесплатно) и **продажа** (мастеру или клиенту мастера, с оплатой и автором-админом = апсейл, см. 05).

## Модель

- **Product**: название, категория (расходники / уход / другое), единица, остаток (денормализованный), закупочная цена, цена продажи, порог. Мягкое удаление.
- **StockMovement**: kind = `purchase` | `sale` | `consume` (обеспечение площадки) | `refund` | `adjust`; delta со знаком, автор, дата, примечание, ссылки (sale_id, booking_id для consume).
- **Sale**: позиции (товар, qty, цена продажи и себестоимость **зафиксированы на момент продажи**), покупатель (master_id **или** разовый контакт клиента мастера), сумма, способ оплаты (баланс мастера / наличные / карта), **admin_id (автор/апсейл)**, связь с бронью опционально, статус (оплачена/отменена/возвращена).

## Сценарии

1. Закупка → остаток растёт, средневзвешенная себестоимость.
2. Продажа мастеру: корзина → остаток проверяется → sale + движение + `charge` с баланса (или внешняя оплата) **в одной транзакции**; 409 если не хватает остатка.
3. Продажа клиенту мастера (уход): разовый контакт (имя+телефон, без аккаунта CRM), оплата наличными/картой, автор — админ (апсейл).
4. Внутреннее потребление (обеспечение площадки): списание без оплаты, автор + причина (бронь/уборка).
5. Порог → уведомление владельцу.
6. Возврат: сторнирующее движение + `refund`, sale → `возвращена` (частично — пропорционально).

## Инварианты

- Остаток = Σ движений; обновление в одной транзакции; запрет минуса (lock позиции).
- Себестоимость/цена в позициях sale не меняются задним числом.
- Возвраты — только движениями.
- Каждая продажа имеет автора; если автор — админ, она попадает в апсейлы (05).

## API (эскиз)

- `GET/POST /products`, `PATCH/DELETE /products/{id}` (владелец/админ); мастер — каталог read-only + цены.
- `GET /stock/movements?kind=&from=&to=`; `POST /stock/purchase`, `/consume`, `/adjust` (основание).
- `POST /sales` {items, buyer: master_id | {name, phone}, payment: balance|cash|card, booking_id?} → атомарно: остатки + sale + платёж; `GET /sales`, `POST /sales/{id}/refund`.

## UI

- «Склад»: позиции, остатки, пороги, история; закупка/списание/ревизия.
- «Касса»: корзина, выбор покупателя (мастер из списка / разовый контакт), оплата, чек; автор — текущий админ.
- У мастера: каталог + «купить» с баланса.

## Задачи и критерии готовности

1. Модель + транзакционный сервис движений; тест гонки на остаток.
2. Продажи атомарно с оплатой (интеграция 04); апсейл-привязка (05).
3. Возвраты, пороги-уведомления, привязка consume к брони.
4. UI склада/кассы/каталога.
5. Готово, когда: продажа списывает остаток и деньги атомарно (409 без изменений при нехватке), возврат возвращает и товар и деньги, каждая продажа админа видна в апсейлах.
