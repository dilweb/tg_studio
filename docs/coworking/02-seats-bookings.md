# 02. Рабочие места (4 шт.) и бронирования — план работ

Первая итерация. Без денег (счёт на оплату подключаем в 04, но сразу закладываем hold и статусы). Главное: **4 места, у каждого свой календарь**, бронь без пересечений и дублей.

## Цели

1. exactly 4 места в настройках (создание/удаление мест — через «Настройку мест», MVP фиксируем 4, но сущность допускает N).
2. **Календарь каждого места** — отдельная лента: брони + блокировки этого места. Общий календарь студии = объединение 4.
3. Мастер: выбирает дату/интервал → видит, какие места свободны → выбирает → создаёт бронь (статус `ожидает_оплаты`, дедлайн hold).
4. Серверная проверка доступности при создании/изменении + защита от гонок.
5. Отмена (с правилом 24ч из 04), перенос, продление — с проверками и историей.
6. Блокировки мест (уборка/ремонт) — владелец/админ.

## Сущности

- `Seat`: id, имя/номер, оснащение, активна. Индивидуальные ценовые правила — см. 03 (связь price_rule.seat_id nullable = «все места»).
- `StudioHours`: день недели → интервалы работы.
- `SeatBlock`: seat_id (или вся студия), [start, end), причина, автор.
- `Booking`: master_id, seat_id, start, end, status, hold_deadline, price_snapshot (JSON: части расчёта + итог — заполняется в 03/04), paid_amount, фактические отметки (nullable), created_by.
- `BookingEvent`: история (создана/перенесена/отменена/продлена/начата/завершена/неявка/истекла), автор, время, детали.

## Инварианты

1. Активные брони (`ожидает_оплаты`, `подтверждена`, `начата`) одного места не пересекаются; блокировки — занятые интервалы.
2. Проверка+вставка в одной транзакции (advisory lock по seat_id или exclusion-constraint по tstzrange). Тест: N параллельных запросов → 1 бронь.
3. Границы: start<end, мин. длительность и шаг — из настроек студии; бронь целиком в часах работы студии; буфер между бронями — из настроек.
4. Мастер по умолчанию не держит две активные брони на пересекающееся время (исключение — админ).
5. Hold истекает → `истекла_оплата` (фоновая задача), место свободно.

## API (эскиз)

- `GET /seats` — 4 места + оснащение; `PATCH /seats/{id}` — владелец (имя, оснащение, активность).
- `GET /seats/{id}/calendar?from=&to=` — **календарь конкретного места**: брони + блокировки.
- `GET /calendar?from=&to=` — общий календарь студии (все места, с фильтром по месту).
- `GET /bookings/availability?start=&end=` — свободные места на интервал.
- `GET /bookings?seat_id=&status=&from=&to=` — мастер видит свои, админ/владелец — все.
- `POST /bookings` {seat_id, start, end} → 201 (со счётом/hold) или 409 с конфликтом.
- `GET /bookings/{id}`, `PATCH /bookings/{id}` (перенос), `POST /bookings/{id}/cancel` (причина; правило 24ч — в 04), `POST /bookings/{id}/extend`, `POST /bookings/{id}/start|complete|no-show` (админ/владелец).
- `GET/POST /blocks`, `DELETE /blocks/{id}`.
- Все изменения → `BookingEvent`.

## UI

- Мастер: раздел **«Календарь»** — сетка 4 мест (или выбор даты → свободные слоты), создание брони, «Мои брони».
- Владелец/админ: общий календарь студии с фильтром по месту, управление блокировками, список всех броней.
- Владелец: раздел **«Настройка мест»** — карточки 4 мест (имя, оснащение, активность) + переход к ценам (03).

## Задачи

1. Модель+миграция: seats, studio_hours, seat_blocks, bookings, booking_events; индексы (seat_id,start), (master_id,start); защита пересечений на уровне БД.
2. Сервис доступности + транзакционная защита; тест на гонки.
3. CRUD мест/часов/блокировок, календари места/студии.
4. CRUD броней + hold/TTL (задача beat) + история.
5. Права: мастер — только свои брони; админ/владелец — все + отметки.
6. Фронтенд: календарь мест у мастера, общий календарь, «Настройка мест», «Мои брони».
7. Тесты: пересечения, гонки, TTL, границы, права.

## Критерии готовности

- 4 места с отдельными календарями видны и редактируются.
- Мастер бронирует свободное место; конфликт → 409; параллельные запросы не плодят дублей.
- Hold истекает, место освобождается.
